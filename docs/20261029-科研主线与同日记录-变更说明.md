# 科研主线与同日记录维护说明

日期：2026-10-29。适用资产：AI4SCIENCE、AI4PROGRAMMING及all安装档案中的相关角色、PR/SR规则、记录模板和工具。稳定Agent/Skill名称、档案成员与安装器边界保持。

## 1. 需要改变的行为

- 优先分析已有性能证据，科研负责人维护一个最高优先任务和最多两个后续候选；新实验必须对应主线要点和能改变的判断。
- 已批准目标内的必要修复、恢复、剩余单元和汇总接续执行；运行、任务完成和科学接受分开。预算/权限/科学条件变化只暂停受影响部分。
- 正确性与过程检查保留内部依据，不以检查数量或文件数量充当科研进展；对外呈现性能结果、范围和确有影响的风险。
- 同项目、实际上海记录日和规范类型只用一个可编辑文件；不同真实任务是独立条目，不按Agent、角色、阶段、目录或格式拆分。

## 2. 来源与生成边界

专业步骤改在sr-doctoral-research/catalog.json；主对比、可复现运行、结果完整性和资源调度的专业字段位于sr-research-shared/references/record-templates/special。通用正文、基础模板和角色约定由各自源文件维护，再统一生成叶技能、68份输出模板与资产清单，不手改生成副本。

命名规范取消同日多批次增加运行编号的办法。ps_01记录工具使用项目配置定位固定日文件，summary只作条目标题；script-api仍按接口对象生成实体文档并默认拒绝覆盖。新的中文条目模板只包含字段与填写要求，不含具体项目事实。

## 3. 日记录约定

文件schema为daily-record/1.0，包含project_id、record_date、record_type、record_profile、timezone等文件级元数据；每条以daily-entry JSON和稳定锚点保存。event_key、attempt_id和内容共同支持幂等，重复提交不再建文件；更正用新条目/事件并关联revision_of，跨日明确项目相对文件和条目锚点。多写入者通过锁、版本比较和原子替换防止覆盖。

软件日志需要需求ID；科研日志需要研究要点及出处，科研成果条目保留SR编号。原始run、数据输入、源码配置、正式论文/手册/API、交付包和签署原件按对象/版本保留，日记录只引用。历史材料原位只读，不能自标归档或用目录级豁免隐藏新的重复记录；没有实际内容不创建每日占位。

## 4. 兼容与限制

日记录写入由旧“新任务新文件”变为“定位规范类型后追加条目”，不能沿用任意内容简述生成过程文件。派生项目根规则中逐叶独立文件、同日交接换名、按角色建第二套记录以及每原子动作完整日志等相反要求，必须与新策略同步替换。

本仓不负责迁移派生项目已有材料，不自动执行昂贵实验、改变科学主张、安装全局能力或发布资产。旧模板发行快照和旧记录保持原件，独立评审与真实科学/资源决定不被文件合并取代。

## 5. 集成检查与恢复

维护时从通用沟通来源、叶技能生成器和record-templates模块重新生成，再运行仓库validate、生成一致性检查及tests；修改资产后更新manifest和资产索引。实际通过状态以提交前真实执行为准，本说明不代替运行结果。

恢复只针对本次规则、模板、脚本与生成产物版本，不删除派生项目已写入的真实条目或运行产物。回到旧版本前需检查daily-record格式兼容，不能把旧工具拒绝追加误认为需要覆盖日文件。
