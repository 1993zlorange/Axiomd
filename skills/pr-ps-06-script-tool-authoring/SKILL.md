# 脚本工具编写

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

为可重复操作编写或审查脚本，并提供中文使用说明；适用于批处理、校验、转换和项目辅助工具。按任务内容自然使用，不要求用户说出技能名或指定姓名。

## 先看什么

先读用户请求、适用的项目说明和直接相关的现有材料。已有决定继续有效，只询问会实质影响结果的缺失信息。

## 怎么做

1. 明确输入、输出、参数、运行环境与错误表现，检查是否已有可复用工具。
2. 实现参数化路径和输入校验；涉及写入时提供预览或明确写入参数，避免默认覆盖用户文件。
3. 定义退出码、错误信息、重复执行、并发冲突和失败清理方式，必要时保留备份。
4. 同步编写命令示例与参数说明，运行正常、错误路径和重复执行检查。

一次性简单命令无需包装成长期工具。执行外部程序使用参数列表，限制目标路径，不引入隐式联网或发布动作。

## 交付什么

按实际用途选用本目录模板，删除不适用部分；简单回答无需另存。过程记录按项目、上海记录日和规范类型定位唯一日文件，任务为独立条目，不按内容简述或运行ID拆文件；无真实内容不创建。正式方案、API说明、手册等实体文档按对象身份持续维护，不能换名规避日记录规则。

## 怎么检查

脚本与使用说明一致，有实际运行证据，错误不会伪装成成功。

本技能直接完成其范围内工作，必要方法已写入本目录。使用现有工具，不递归调用其他技能，不为普通任务增加管理表、额外角色或重复确认。


## 工程文档按对象维护

docs仅保存当前代码的使用与维护说明：README导航、architecture实际结构、api接口导航，以及interfaces、commands、algorithms、adr。相同模块、脚本组或文件格式维护唯一当前正文，使用稳定对象名，日期与适用版本放元数据，不因修复或每次运行新增日期API文档。简单脚本优先--help及必要注释，相关脚本共用运行指南；复杂独立工具确需说明时维护一份对象文档。文档必须讲输入输出、错误、限制及真实命令，不能以目录模板补造未实现能力。

工作契约、工程交付/复验、检查成绩、修订流水、补丁和源码快照不进入docs，必要原始证据留既有run。旧的“每个新脚本新增日期API说明”要求由本节替代；这是维护现行说明，不取消必要用法文档。科研结果、图表解释和主张归achieve并引用唯一原始来源。架构决定按实际决定对象保留，不为普通修复或文件整理另写ADR。

迁移前检查当前代码、配置、命令及历史来源绑定；被封存运行绑定的原件不得覆盖、改指纹或改写旧manifest。保留原路径只读例外须逐文件登记原SHA与用途并在导航标明非现行稿，其余旧件移出日常docs。归并先提取有效字段、边界及运行语义，过程部分原件保全。文档唯一性按对象/适用版本判断，不把不同模块同日的合法文档并成一个日文件。新目录有实际文档才建，工程检查不进入科研日志。
