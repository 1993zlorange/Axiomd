# 需求澄清

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

通过已有材料和少量关键问题弄清谁遇到什么问题、希望得到什么结果；用于想法模糊、目标冲突或方案先于问题的请求。按任务内容自然使用，不要求用户说出技能名或指定姓名。

## 先看什么

先读用户请求、适用的项目说明和直接相关的现有材料。已有决定继续有效，只询问会实质影响结果的缺失信息。

## 怎么做

1. 读已有说明、代码和讨论，分清已知事实、用户决定、推测和缺失信息。
2. 用一句话描述使用者、当前困难和期望变化；检查现有替代做法以及不做的代价。
3. 只询问会改变范围、成本或成功标准的问题，每次聚焦一个主要决定，给推荐及理由。已经明确的执行请求直接进入工作。
4. 用反例、失败情形和最小方案检验需求，写出必要功能、非目标、限制与可观察的完成标准。
5. 输出简洁的理解记录和真实待决定项；用户已给出的明确要求作为依据，不要求重复确认整份文件。

本技能负责消除歧义，不同时承担完整需求文档或实现。不要为了凑访谈轮次持续提问。

## 交付什么

按实际用途选用本目录模板，删除不适用部分；简单回答无需另存。过程记录按项目、上海记录日和规范类型定位唯一日文件，任务为独立条目，不按内容简述或运行ID拆文件；无真实内容不创建。正式方案、API说明、手册等实体文档按对象身份持续维护，不能换名规避日记录规则。

## 怎么检查

读者能说清要解决什么、为什么要做、做到什么算好；未知信息与结论分开。

本技能直接完成其范围内工作，必要方法已写入本目录。使用现有工具，不递归调用其他技能，不为普通任务增加管理表、额外角色或重复确认。
