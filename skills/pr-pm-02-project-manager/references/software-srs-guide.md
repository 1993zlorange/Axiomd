# 软件需求规格说明

在目标清楚后描述系统或模块的外部行为，使实现者与测试者能得到相同理解。先写范围、环境、使用者、前提和术语，再写功能、数据、接口与质量要求。

## 功能与场景

每项需求写编号（已有时保留）、目的、触发、前置条件、输入、处理规则、输出、状态变化、错误和完成条件。每个用例包括正常流程、替代流程和失败处理。不能仅列模块名称。

## 数据与接口

数据字典列字段含义、类型、单位、范围、缺失规则、来源和生命周期。说明保存、删除、访问权限和版本兼容；具体数据库索引与事务实现放入设计。

接口列调用方、被调用方、协议、参数、响应、错误、权限、超时及幂等要求。异步任务还需提交、查询、取消和恢复的可见行为。

## 质量与验证

性能、可靠性、离线、隐私、部署和兼容要求必须有条件和阈值。每项重要需求指定测试、演示、检查或分析方式，标出依赖与未确定事项。用户原始目标优先，不能为了格式发明新需求。
