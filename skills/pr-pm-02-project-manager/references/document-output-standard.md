# 文档输出规范

所有生成的 Markdown 或 HTML 文档都必须遵循本规范。文档应当是可评审的空白架构，而不是未经组织的叙述堆积。

## 命名

每份交付文档统一命名为 `YYYYMMDD-内容简述-文档类型.扩展名`，由生产日期、稳定的内容简述和文档类型组成。例如：`YYYYMMDD-内容简述-需求文档.md`、`YYYYMMDD-内容简述-设计方案.md`、`YYYYMMDD-内容简述-用户手册.md`、`YYYYMMDD-内容简述-项目阶段汇报.html`。

不得覆盖较早日期的交付物。将日期写入文档元数据字段 `produced_at`，保留稳定的文档 ID，并将治理基线与状态（`draft`、`proposed`、`approved`、`implemented`、`verified`、`accepted`）分开记录。

## 必备空白架构

每份文档至少包含：

1. 元数据、负责人、生产日期、状态、治理基线和变更记录；
2. 目的、范围、非目标、假设和待决策事项；
3. 带来源路径和版本的输入/证据；
4. 与文档类型对应的正文结构；
5. 到需求、设计、测试或科研工作契约的可追溯关系；
6. 结论边界、限制条件和需要人工决策的节点；
7. 包含产物路径、证据、结论和下一步行动的闭环记录。

未知值保留为 `TBD` 或 `Not run`；不得臆造批准、证据、日期、指标或科研结果。

## 基线参考原则

生成项目文档时，使用目标项目当前批准的需求基线、架构基线、用户手册基线和阶段状态基线（如存在）。这些基线仅作为结构和治理参考，不得复制过期的主张或历史状态；模板本身不绑定任何具体文件名、项目名称或日期。
