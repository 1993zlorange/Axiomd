# 工作方法改进评估

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

汇总一段时间内的实际问题和使用结果，判断哪些规则或技能值得保留、合并、改进或删除。按任务内容自然使用，不要求用户说出技能名或指定姓名。

## 先看什么

先读用户请求、适用的项目说明和直接相关的现有材料。已有决定继续有效，只询问会实质影响结果的缺失信息。

## 怎么做

1. 确定时间范围，收集真实需求变化、失败、反馈和维护成本。
2. 找重复问题、重复功能、误触发和低价值步骤，区别个别特例与持续问题。
3. 比较保留、简化、合并和删除的收益及影响，优先选择小改动。
4. 给出有依据的改进建议与验证样例，用户要求实施时按其范围落实。

本技能评估一段时间内的方法效果，不代替单个故障复盘，也不自动修改所有全局设置。

## 交付什么

按实际用途选用本目录模板，删除不适用部分；简单回答无需另存。过程记录按项目、上海记录日和规范类型定位唯一日文件，任务为独立条目，不按内容简述或运行ID拆文件；无真实内容不创建。正式方案、API说明、手册等实体文档按对象身份持续维护，不能换名规避日记录规则。

- [20260912-进化评估-输出模板](assets/20260912-进化评估-输出模板.md)

## 怎么检查

每项建议有使用证据和可验证预期，不用活动数量代替效果。

本技能直接完成其范围内工作，必要方法已写入本目录。使用现有工具，不递归调用其他技能，不为普通任务增加管理表、额外角色或重复确认。
