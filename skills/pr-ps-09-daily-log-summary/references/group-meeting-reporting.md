# 科研日志与组会汇报

版本：group-meeting/1.0；来源：《科研写作与表达·配套写作要点》v1.4，第四章，正文18—24页；2026-10-30核对。下列为表达要求的适配，不是科学结果。

每项工作同时对应真实研究问题及可定位出处、组会章节及问题。4.1进展Q1—14；4.2调研Q1—16；4.3方案取舍Q1—17；4.4实验Q1—14；4.5失败异常Q1—14；4.6结尾答问Q1—15；4.7页面表达Q1—14。编码如4.4.Q10。只选适用问题，不机械填齐。

正文：当前问题（4.1.Q1—Q2）→本次行动和产物（Q3—Q4）→新认识及依据（Q5—Q8）→差距及影响（Q9—Q12）→下一步、标准与请求（Q13—Q14）。实验补充4.4的主张、控制条件、对照、指标、实际范围和不确定性；调研按4.2呈现研究入口；方法按4.3说明取舍；科学异常按4.5说明结果影响。结尾按4.6，表达按4.7。

仅literature、method、performance、analysis、writing、research_blocker可作为科研进展；类别标签不替代内容复核。调研、方法和写作须实际改变研究问题、方法或论证；不强填性能数字。performance与analysis须比较条件和指标。保留正、零、负结果、未完成范围与不能支持的判断。

代码正确性、格式/哈希、登记、角色流转、工具修复及其成绩，不进入正文或附录；必要证据留原工程run，不另造内部日报。缺陷影响性能数据时仅说明作废范围、科学影响和必要重跑，不叙述检查过程。无真实科研进展不建日志。

同日同类型只有一个可编辑母版。汇总不得另建可编辑日报；按需导出的HTML/PDF须声明母版且不可独立追加。明确请求的周报按时间范围维护，不自动每日另建。研究记录时间与实际发生时间分开，历史重建明确来源日期、日期不确定性和真实整理时间，不倒填当时已记录。

机器字段report_contract、work_kind、research_point、research_source、guide_questions、research_question、actions、result、interpretation、limitations、next_step、evidence必须保留；性能/分析还需comparison_conditions、metrics。写前核实际来源，字段结构不能证明内容科学性。正文使用日常中文及简短来源链接，机器身份不堆在可见正文。


组会要点在可见正文中必须写出具体问题，不能只显示4.4.Q10一类编号。编号保留在机器元数据便于核对，生成器按group-meeting-questions.json展开。面向领导和导师，用完整句说明做了什么、结果说明什么、还有什么不足、接下来做什么；首次解释必要术语，禁止未解释的A/B/C、S0/S1、宏、固定流、待决等简称。保留所有必要数字、条件、负结果和结论边界，不能把改写写成新实验。
