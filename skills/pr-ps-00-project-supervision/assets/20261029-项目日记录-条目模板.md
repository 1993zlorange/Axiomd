# 项目日记录条目空白模板

本模板只说明字段与填写规则，不是可直接写入的实际记录。没有真实结果时不创建日文件，不为补齐类型生成记录。先按项目根的record_policy定位当天规范类型；同一天不同任务使用同一文件内的独立条目。

## 1. 必填内容

| 字段 | 填写规则 | 验收标准 |
|---|---|---|
| entry_id | 稳定条目ID，只用字母数字、点、下划线或连字符 | 唯一，不因换标题或排序而改变 |
| event_key | 同一真实事件的稳定键 | 重复提交可识别；新一天真实进展或修订使用新事件身份 |
| content | 实际工作与结果，区分已执行、计划和未执行 | 不复制成套管理流水，不把检查成绩当研究结果 |
| impact | 对需求或研究判断的实际影响 | 与结果分开，不能用目标代替原因或影响 |
| status | 该条事项的真实状态 | 不代表同日日文件全部完成或通过 |

## 2. 按用途补充

- 软件日志填写requirement_id；科研日志填写research_point和research_source，指向真实研究要点及出处。
- 科研成果填写sr_id及必要agent/workflow，正文沿单条SR专业模板；只引用实际专题产物，不再复制全文。
- attempt_id仅区分真实尝试；occurred_at可记录与实际记录时间不同的真实发生时刻，必须带时区。
- evidence列可定位来源。revision_of仅在真实更正时填写：同文件原entry_id，跨日为项目相对文件#entry-原ID；新修订使用新entry_id和修订事件键。
- background可简述必要背景。recorded_at、日期、类型和profile由工具维护，不伪造或倒填。

## 3. JSON空白结构

删除不适用的可选字段并填入真实内容后，才交给记录工具。下列占位文本不能当真实事件提交。

```json
{
  "entry_id": "<稳定条目ID>",
  "event_key": "<真实事件键>",
  "attempt_id": "<真实尝试身份>",
  "content": "<实际工作及结果>",
  "impact": "<对目标的实际影响>",
  "status": "<该条真实状态>",
  "requirement_id": "<软件需求ID；非软件日志时按用途删去>",
  "research_point": "<科研要点；非科研日志时按用途删去>",
  "research_source": "<科研要点原文出处>",
  "sr_id": "<科研成果对应SR编号；不适用则删去>",
  "occurred_at": "<带时区的真实发生时间；不需要则删去>",
  "evidence": ["<项目相对来源或文件#条目锚点>"],
  "revision_of": "<原条目ID或项目相对文件#entry-原ID；非修订则删去>"
}
```

## 4. 追加与检查

同一事件/尝试及内容重复不增加条目；内容变更必须新增修订身份而不是覆盖。写入者使用锁和版本核对合并，多Agent不能各开日记。跨日按实际上海记录日记录，发生时间另列。正式成果、固定输入、原始run、源码及配置不强行并入日记；只读导出指向真实母版，不独立维护。
