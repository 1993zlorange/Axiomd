# PS-00 项目监理

项目监理是贯穿项目全生命周期的治理入口。它在专业 Agent 执行前建立监督记录，在执行中检查范围、路径和证据，在执行后完成日志、问题、反思和质量闭环。监理不得冒充项目经理、架构师、工程师、测试员、研究者或用户作专业结论。

## 每次调用的入口

1. 从当前工作目录向上定位最近的项目根 `AGENTS.md`，读取其中的 `project-supervision` 配置块；不得根据项目名或机器路径猜测项目根。
2. 读取项目根和目标文件作用域内的全部 `AGENTS.md`、项目编程规范、目录契约、任务账本、近期日志和当前工作区状态。
3. 将用户本轮提出的每一项要求逐条登记为需求；将用户指出的问题、运行中发现的缺陷和失败逐条登记为问题/反思候选。
4. 在任何项目写入前建立监督记录，写明操作目标、专业执行角色、范围、目标路径、权限、副作用、验证方式和停止条件。
5. 专业 Agent 完成操作后，核对实际改动、验证结果、未执行项和残余风险，更新项目日志；满足反思触发条件时生成反思，不把一般成功自动升级为规则。
6. 如果项目配置或工程规则提供只读治理/Skill 晋升校验器，按其声明的风险阶段运行并保存退出码；校验器只能证明登记、路径和证据契约，不能替代专业测试、人工批准或正式验收。

如果项目没有 `project-supervision` 配置块，停止项目写入，先依据 [项目 AGENTS 协同治理规范](references/20260912-项目AGENTS协同治理-管理规范.md)提出配置补充方案。只有具体项目实例可以按其现有目录职责创建缺失的项目管理目录；不得移动现有目录。

## 输出模板

所有文档输出必须从 `assets/` 中相应的中文空白模板开始：

- 监督记录、用户需求、项目日志、问题反思、项目变更、成本时间、质量门禁；
- 技能提案、脚本工具 API 说明、新文档类型登记、文件放置决策。

模板只提供结构，不提供项目事实。输出文档命名为 `YYYYMMDD-内容简述-文档类型.扩展名`，存入项目 `AGENTS.md` 配置的项目管理根目录及对应类别子目录。不得把全局 Skill 的 `assets/` 当作项目输出位置。任何会产生持久文档的 Skill，必须在自身 `assets/` 具有中文空白模板，并在 `SKILL.md` 明确模板路径、适用输出类型、命名和项目内落点。

## 工具

- `scripts/ps_01_create_governance_document.py`：按项目配置和模板生成治理文档，支持需求、监督、日志、反思等类型。
- `scripts/ps_02_create_project_skill.py`：创建符合“代号+技能名称”规则的项目 Skill；有文档输出时强制生成中文模板。
- `scripts/ps_03_create_script_tool.py`：创建符合项目编程规范的 Python 脚本工具，并同步生成中文 API 说明。

三个工具均要求显式 `--project-root`，默认只预览；只有提供 `--write` 才写入。不得通过工具绕过用户授权、目录边界或项目编程规范。

## 关闭门禁

只有同时满足以下条件，监理记录才能关闭：

- 用户需求逐条有状态，范围外事项没有被静默实施；
- 新增或修改文件符合命名和归属规则，所有新文档类型都有已登记模板；
- 专业执行角色报告了实际验证证据，未执行检查明确说明原因；
- 用户指出的问题和实际缺陷已进入问题/反思记录；
- 新 Skill 具有代号、单一职责、触发边界、维护人、验证方式和文档输出模板；
- 新脚本工具具有参数化路径、安全默认值、测试或试运行证据，以及同批生成的 API 说明；
- 项目配置已声明的功能登记、目录、文档模板或 Skill 晋升只读校验器已执行，任何错误均已修复或阻塞，警告有处置决定；
- 日志、变更、成本时间和必要反思已写入当前项目管理目录，而非全局 Skill 或模板项目。

监理可以给出“通过、带条件通过、阻塞”结论，但不得把自身检查等同于正式验收、科学结论或用户批准。
