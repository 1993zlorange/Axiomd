# 项目工作检查

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

检查项目工作是否漏掉用户要求、文件安排或必要验证；用于用户要求整体复核，或项目已有明确检查规则的场景。按任务内容自然使用，不要求用户说出技能名或指定姓名。

## 先看什么

先读用户请求、适用的项目说明和直接相关的现有材料。已有决定继续有效，只询问会实质影响结果的缺失信息。

## 怎么做

1. 读取当前请求、适用的项目说明和已有修改，列出本次要完成的事项。
2. 对照文件和实际结果检查是否遗漏要求、误改无关内容、放错目录或缺少必要验证。
3. 优先处理会导致结果错误、数据损失或无法使用的问题；普通命名和文字问题随当前修改修正。
4. 项目已有记录要求时更新对应记录；没有配置时沿用当前项目约定，不为普通工作强制建立管理目录。
5. 交付检查结果、证据、未完成项和下一步，区分自检、用户确认和正式验收。

不自动调用其他角色或技能，不为每次回复生成一套文档。保留用户明确要求的记录和检查，不以本技能代替专业判断。

## 交付什么

按实际用途选用本目录模板，删除不适用部分；简单回答无需另存。过程记录按项目、上海记录日和规范类型定位唯一日文件，任务为独立条目，不按内容简述或运行ID拆文件；无真实内容不创建。正式方案、API说明、手册等实体文档按对象身份持续维护，不能换名规避日记录规则。

## 怎么检查

本次要求都有明确结果，重要风险有处理说明，检查依据可以打开；缺失项如实说明。

本技能直接完成其范围内工作，必要方法已写入本目录。使用现有工具，不递归调用其他技能，不为普通任务增加管理表、额外角色或重复确认。
