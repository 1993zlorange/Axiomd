# Skill 与脚本工具生成技术规范

## 1. 新 Skill

新 Skill 的目录和 frontmatter `name` 必须采用 `<代号>-<英文技能名称>`，例如 `ds-01-validate-dataset`。代号在当前项目的技能登记表中唯一；目录使用小写字母、数字和连字符，名称不超过 64 个字符。

每个 Skill 至少定义：单一职责、触发条件、非目标、前置输入、执行流程、输出、失败边界、权限、幂等/并发、验证命令、维护人和进化指标。项目专例、固定机器路径、凭据、自动提交/推送和隐式外部写入不得进入通用 Skill。

凡 Skill 会生成 Markdown、HTML、报告、日志、说明、配置说明或其他文档，必须在该 Skill 的 `assets/` 中提供对应中文空白模板，并在 `SKILL.md` 明确选择规则、文件名和项目内落点。新增文档类型必须同时登记其文档类型、目录和模板。

新 Skill 必须先生成技能提案，再小范围试点；验证正常、边界、无效输入、失败、重复执行和权限路径。人工批准后方可升级为默认项目或全局能力。

## 2. 新反思

反思使用项目监理的反思模板，通过 `ps_01_create_governance_document.py --type reflection` 创建。反思必须写入当前项目配置的反思目录，不能写入全局 Skill。每份反思使用 `YYYYMMDD-内容简述-反思.md`，包含证据、根因分类、最小改进、责任人、验证和是否提议 Skill 演化。

## 3. 新脚本工具

脚本文件遵循项目编程规范；Python 使用 `snake_case.py`，函数/变量用 `snake_case`、类用 `PascalCase`、常量用 `UPPER_SNAKE_CASE`。脚本接收显式项目根或输入输出参数，不读取开发者固定目录，不隐式联网，不动态执行不可信代码。

写入型工具必须默认预览，并以显式 `--write` 或项目等价约定开启写入；定义输入、输出、退出码、幂等、冲突、回滚、安全和示例。每个新脚本必须在同一操作中生成 `YYYYMMDD-内容简述-API说明.md`，写入项目配置的工具文档目录。缺少 API 说明或验证证据时不得关闭任务。

## 4. 脚本 API 文档最低内容

工具标识、版本、责任人、源文件、用途、调用方式、参数表、输入输出契约、退出码、错误、安全权限、幂等并发、示例、测试、兼容性、变更记录和回滚方式。

## 5. 新文档类型

如果现有模板无法表达新文档类型，先使用“新文档类型登记模板”明确名称、目的、负责人、命名、落点、字段、证据、保留和验证，然后在适用 Skill 的 `assets/` 中增加中文空白模板并更新 Skill 路由。不得先生成正式文档、事后补模板。
