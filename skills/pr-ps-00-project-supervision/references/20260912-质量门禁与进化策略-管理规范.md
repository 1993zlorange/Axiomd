# 质量门禁与进化策略管理规范

## 1. 分层质量门

| 层级 | 检查对象 | 最低证据 |
|---|---|---|
| L1 静态 | 路径、命名、格式、敏感信息、绝对路径、链接、配置语法 | 命令与扫描结果 |
| L2 单元/契约 | 正常、边界、无效输入、依赖失败、幂等和兼容 | 测试结果与失败清单 |
| L3 集成 | 真实文件、进程、适配器、Schema、日志和产物契约 | 隔离环境运行证据 |
| L4 用户路径 | 项目已有的 CLI、HTTP、UI 或科研工作流 | 可观察结果与状态证据 |
| L5 交付/发布 | 版本、文档、许可证、变更、回滚和可复现命令 | 交付清单与复核结果 |

按变更风险选取层级，不为项目不存在的能力虚构检查。错误阻断交付；警告必须有处置决定；未执行必须记录原因。

## 2. 文档和数据质量

对文档、数据、实验和生成产物至少检查正确性、一致性、完整性、规范性和可追溯性。指标记录当前值、目标值、样本范围、公式、环境和时间。静态字符串命中、代码存在或单张截图不能单独证明业务结果或科学结论。

## 3. Skill 进化策略

进化输入包括所有用户要求、问题记录、反思、质量门禁、成本时间和误触发记录。采用以下生命周期：候选经验 → 技能提案 → 小范围试点 → 独立评审 → 人工批准 → 启用 → 监控 → 优化、合并或淘汰。

满足以下条件才建议新增或优化 Skill：问题或需求具有重复性；现有 Skill 无法覆盖；规则可迁移；输入输出和失败边界明确；收益可测；维护人已确定。单个项目特例、单次成功和未经验证的偏好不升格为全局规则。

## 4. 周期与触发

每达到项目 `AGENTS.md` 配置的反思数量阈值、重复问题阈值或评估周期，生成一次演化评估。评估输出：样本范围、重复模式、候选改进、与现有规则的重叠、预期收益、风险、试点范围、回滚和人工决定。

监理只能提出和验证改进，不能自动修改全局 Skill、代理配置、权限策略或项目基线。
