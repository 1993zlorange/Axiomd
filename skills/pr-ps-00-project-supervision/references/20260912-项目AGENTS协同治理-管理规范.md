# 项目 AGENTS 协同治理管理规范

## 1. 双层治理

项目建立时，由项目监理读取项目根 `AGENTS.md` 和工程目录内更具体的 `AGENTS.md`。根文件定义全项目治理、项目管理目录和强制监理入口；工程文件定义代码、测试、数据、实验、文档和脚本的局部规范。子目录规则可以收紧或补充根规则，不得取消需求登记、日志、反思、命名、归属和质量证据要求。

## 2. 强制入口

根 `AGENTS.md` 必须明确：每次项目相关操作，包括只读调查、规划、设计、开发、测试、文档、数据、实验、发布、维护和外部系统动作，在开始前调用全局 `pr-ps-00-project-supervisor` Agent（其主 Skill 为 `$pr-ps-00-project-supervision`）。监理完成操作登记后，才由专业角色继续；操作结束后返回监理关闭记录。

## 3. 项目配置块

项目根 `AGENTS.md` 至少包含以下可解析配置，所有值均为相对项目根的路径：

```project-supervision
project_management_root = "project-management"
requirements_dir = "requirements"
supervision_dir = "supervision"
logs_dir = "logs"
reflections_dir = "reflections"
changes_dir = "changes"
quality_dir = "quality"
costs_dir = "costs"
skills_dir = "skills"
tools_dir = "tools"
templates_dir = "templates"
engineering_root = "."
programming_standard = "PROGRAMMING_STANDARDS.md"
evolution_review_days = 14
repeat_problem_threshold = 3
```

项目建立者应优先映射到现有目录。只有具体项目确认不存在合适位置且确有首份产物时，才创建配置中的目录；创建后同步目录说明。不得把上述示例值当成 Agent 或脚本中的固定路径。

## 4. 路径解析

1. 用户显式给出的项目根优先。
2. 否则从当前目录向上寻找最近且包含 `project-supervision` 配置块的 `AGENTS.md`。
3. 所有配置路径相对于该项目根解析，并校验解析结果仍位于项目根内。
4. 缺少、重复、越界或含占位符时阻塞写入，交由项目建立者补齐。

## 5. 项目建立检查

项目建立者与监理共同确认：项目目的和边界、工程根、项目管理根、编程规范、文件命名、各类归属、质量命令、权限、日志反思周期、Skill 代号注册、脚本/API 说明规则和归档策略。空白目录不是功能承诺，不得为了填满模板生成无调用方文件。
