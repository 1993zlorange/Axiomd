# 需求、日志和复盘

需求说明用户要什么；日志说明实际做了什么；复盘说明出现了什么问题、原因与改进。按用户或项目的实际要求保存，不为每个普通动作生成三份文件。

需求保留原意与变化，重要事项写清范围和完成条件。日志区分完成、失败、未执行和计划，引用真实文件与检查结果。时间和成本没有记录就写未知。

复盘针对实际缺陷或重复问题，先定位原因，再提出少量可检验的改进。一次成功或偏好不自动升级为全局规则。明确授权的修改可以实施，超出范围时只提出具体建议。

已有正式管理文档遵循 [写作标准](20260929-管理文档写作标准-管理规范.md)，使用 A/B/C 对应模板。该标准用于确实需要的文档，不作为启动普通工作的前置条件。
