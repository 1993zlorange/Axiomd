# 交付质量检查

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

按变更影响检查代码、文档、数据或实验交付质量；用于提交、交付前的集中复查。按任务内容自然使用，不要求用户说出技能名或指定姓名。

## 先看什么

先读用户请求、适用的项目说明和直接相关的现有材料。已有决定继续有效，只询问会实质影响结果的缺失信息。

## 怎么做

1. 列出当前改动及可能影响的行为，选择与风险匹配的检查。
2. 代码检查实际行为和项目要求的测试；文档检查准确性、可读性和链接；数据检查结构、范围、缺失与重复；图表检查来源和可读性。
3. 记录命令、输入版本、实际结果和未执行原因，不重复运行无变化且已有可靠结果的检查。
4. 修复当前范围内的问题并复查，最终给出通过、未通过或未能验证的结论。

本技能组织交付检查；独立功能测试与正式用户验收是不同结果，不能互相冒充。

## 交付什么

按实际用途选用本目录模板，删除不适用部分；简单回答无需另存。过程记录按项目、上海记录日和规范类型定位唯一日文件，任务为独立条目，不按内容简述或运行ID拆文件；无真实内容不创建。正式方案、API说明、手册等实体文档按对象身份持续维护，不能换名规避日记录规则。

## 怎么检查

结论与实际检查一致，重大失败没有被隐藏，未检查部分清楚。

本技能直接完成其范围内工作，必要方法已写入本目录。使用现有工具，不递归调用其他技能，不为普通任务增加管理表、额外角色或重复确认。
