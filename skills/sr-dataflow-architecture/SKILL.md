# 数据流与系统架构设计

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

需要把数据来源、处理、模型、评价、存储和模块责任连成可实现数据流时。按用户的任务自然使用，不要求用户说出技能名，也不要求指定负责人姓名。

## 先看什么

## 怎么做

1. 盘点数据来源、处理、输入、输出和评价。
2. 手画端到端数据流与状态边界。
3. 定义每个模块责任、接口和持久化。
4. 沿失败路径检查断点和回退。

## 怎么检查

数据能从来源追到结果，模块责任单一，接口可验证，主要失败有可观测处理。

核对关键数字、来源位置、计算或运行结果；明确哪些是事实、解释、假设和计划。缺少输入时完成能做的部分，并说明缺什么、影响什么。没有运行的实验不能写成已完成，没有证据的推断不能写成结论。
