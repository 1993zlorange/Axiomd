# 科研进展叙事化规则

本 Skill 只做派生展示，不新增科学事实。所有内容必须能追溯到成果卡、交接记录或历史材料。

## 1. 双数据源分级

| 数据来源 | 判定 | 使用规则 |
|---|---|---|
| 成果卡 frontmatter、状态字段、明确日期 | 记录事实 | 可用于时间、状态和已完成事项 |
| 历史文件名、材料时间、不完整记录 | 推断 | 必须标为推断，不与事实混用 |

输出中必须显式说明：

```text
哪些条目来自记录事实；
哪些条目来自推断；
推断依据是什么。
```

## 2. 双带时间线

展示应包含两条时间带：

1. **全程总览**
   - 按月或按阶段展示；
   - 突出阶段转折和里程碑；
   - 不塞入过多日常任务。

2. **重点时期详图**
   - 按日或按工作步骤展示；
   - 区分：
     - 已完成；
     - 进行中；
     - 待执行；
     - 里程碑。

甘特条目悬停应显示：

```text
结论：……
来源类型：事实 / 推断
```

不应只显示文件名或内部编号。

## 3. 逐时间点结论

每个时间点必须有结论行。

允许的结论来源：

- 成果卡的“结论”；
- 成果卡的“发现”；
- 成果卡的“不能得出的结论”；
- 交接记录的当前结果；
- 历史组会材料或实验报告中的原文结论。

禁止：

- 根据文件名猜测科学结论；
- 把计划写成结果；
- 把局部规律推广成总体结论；
- 用“完成”代替科学含义。

提取不到结论时写：

```text
原文未给出结论；本条仅说明……
```

## 4. 白话口径

正文面向不了解项目内部过程的导师或同方向研究者。

必须清除或展开：

- 管理动作词：具名、裁决、转正、验收、派发、台账、建议级、挂旗、closed；
- 治理编号：REQ、HDEC、SUP、CHG；
- 流程编号；
- 实验代号；
- 未解释的英文缩写。

专业术语不一刀切删除。若是研究方向必要术语，首次出现时写：

```text
术语（一句中文解释）
```

## 5. 内容展开原则

凡是影响理解的具体内容，都必须展开：

- 研究假设是什么；
- 比较对象是谁；
- 最近邻工作差异在哪里；
- 求解或实验预算是多少；
- 实验顺序为什么这样安排；
- 结果的物理或科学含义；
- 哪些结论还没有得出。

页面开头应提供“名词速查卡”，每个词条一句大白话。

## 6. 诚实边界不弱化

通俗化不能改变科学事实。

以下表述必须保留其含义：

```text
阈值未定；
无性能结论；
待独立复核；
只描述规律，不下好坏结论；
不能从内插结果推出外推结论；
预算尚未用完或已耗尽。
```

悬停提示、正文和依据表必须同源。不得在正文弱化边界、在脚注恢复边界。

## 7. 渲染和内容验证

交付前检查：

### 布局

- 标签不溢出；
- 同一行不重叠；
- 页面无异常横向滚动；
- 甘特条不侵入标签列；
- 悬停框完整可见。

### 内容

- 每个时间点有结论或明确说明没有结论；
- 事实 / 推断分级完整；
- 管理术语和内部编号无残留；
- 名词速查卡覆盖必要术语；
- 诚实边界未弱化；
- 来源路径可追溯。

### 交互

- 悬停显示和隐藏正常；
- 悬停内容是结论，不只是文件名；
- 键盘或鼠标操作不造成布局错位。

有浏览器工具时必须实际渲染验证。无法验证时写：

```text
渲染验证受阻：<缺少的工具或环境>
```

不得写“验证通过”。

## 交付前检测清单

- [ ] 输入材料全程只读；
- [ ] 输出是派生视图，不替代原始记录；
- [ ] 事实与推断分栏或分标签；
- [ ] 全程总览和重点时期详图都存在；
- [ ] 每个时间点有结论或“原文未给出结论”；
- [ ] 悬停显示结论；
- [ ] 管理术语和治理编号已清除或展开；
- [ ] 必要专业术语有一句话解释；
- [ ] 导师能不看内部流程文档而理解主线；
- [ ] 科学边界没有被弱化；
- [ ] 渲染布局和交互已验证，或如实记录受阻；
- [ ] 所有论断有来源路径。
