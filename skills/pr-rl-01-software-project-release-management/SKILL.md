# 通用软件项目发布管理

仅在用户明确要求发布、打包或准备发布候选时使用。先由项目监理登记版本范围、权限、外部副作用和发布目标；读取已批准需求/设计、变更、质量门、测试结论、迁移/配置、许可证和项目发布约定。

## 发布过程

1. 形成版本清单：源代码/构建产物、锁文件、配置模板、迁移、用户/运维文档、许可证、已知限制、验证和回滚。
2. 核对全部 Must 项、质量门和独立测试结论；未执行项或高风险缺陷必须阻止正式发布或明确降级为候选。
3. 在项目约定的 `release` 责任目录准备可审查资产，在成效目录保存正式发布说明；不把秘密、真实运行日志、内部治理材料、未经授权的数据或来源不明文件放入包内。
4. 只在获得额外明确授权后执行上传、部署、重启、推送、签名或外部写入；否则停在本地候选和记录状态。
5. 发布后记录烟测、实际版本、回滚状态、外部目标和限制，交回项目监理关闭。

## 输出

发布说明必须从 [中文空白模板](assets/20260913-通用软件版本发布说明-模板.md) 开始，命名为 `YYYYMMDD-内容简述-发布说明.md`，写入项目 `AGENTS.md` 指定的交付/发布责任目录。模板提供结构，不构成发布批准或验证事实。

本 Skill 不替代 ScienceResearch 或其他领域项目的专用打包规则；目标项目存在已批准专用发布 Skill 时，由项目经理选择该专用 Skill 并保留本 Skill 的授权、清单、烟测和回滚边界。
