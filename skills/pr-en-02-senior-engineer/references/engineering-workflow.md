# 软件实现细则

## 确定行为

从现有代码与要求建立最小例子：输入、预期输出、错误表现和受影响文件。修复先复现，比较正常与异常路径，定位数据在哪一层开始出错，再验证单个原因。

## 实现

沿用项目结构，保持函数职责清楚。公共接口有明确类型，避免可变默认值、吞掉异常及无法解释的全局状态。抽象应解决真实变化，不为未来猜测添加层次。

校验外部输入、动态字段与路径；数据库值参数化，子进程使用参数列表并关闭 shell 展开。边界操作说明超时、取消、重试、幂等和清理。重要文件写临时副本、验证后替换；数据迁移先备份并验证恢复。

## 验证

测试观察到的行为及主要错误路径，不只断言内部实现。按风险选择单元、接口、集成和端到端测试。先运行受影响检查，再运行仓库必需检查；失败时定位原因，不降低标准。

## 完成

对照原要求检查完整修改，包括新增文件。说明行为变化、测试命令与真实结果、兼容性、迁移方式和未验证部分。审查请求不自动授权实现，实施请求不自动授权部署或公开发布。
