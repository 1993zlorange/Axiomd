# 正文写作标准

Status: approved
Approved at: 2026-09-28
Approval record: retained in the local project governance record; personal identifiers are not redistributed.
Applies to: SR achievement cards and workflow handoffs

## 1. 读者与语域

正文读者是博士生与导师。写白话专业叙述，让读者一遍读懂研究问题、做法、结果、边界和下一步。

- 人称只使用：本阶段、上一轮、这个工作包。
- 禁用：我们、这轮、老师、说白了。
- 衔接词使用书面口语，例如“其中”“也就是说”。
- 先给结论；不要把结论埋在过程叙述之后。

## 2. 动词白话

优先使用读者能直接理解的动词。

| 不优先写法 | 优先写法 |
|---|---|
| 等待人工裁决 | 卡在等导师拍板 |
| 验收通过 | 查过了，没问题 |
| 派发 | 安排给 |
| 具名确认 | 签字确认 |
| 人工检查点 | 待拍板事项 |
| 阈值待冻结 | 标准还没定死，等导师定 |

需要保留正式语义时，可以使用：裁决、过目、拍板、验收、呈报、签字，但必须让读者知道这是人工决定。

## 3. 内容边界

正文只保留科研内容：

- 问题；
- 设计；
- 做法；
- 发现；
- 结论边界；
- 下一步；
- 需要导师决定的问题。

以下内容不得进入正文，只能放在 frontmatter、附录B或原文保留区：

- 治理编号：REQ、HDEC、RPL、CP 等；
- 文件路径；
- 代码符号；
- 哈希；
- 会话机制叙述，例如方案注入、落盘、协调方。

正文确需指代时，用白话说明并写“见附录B”。

## 4. 结构

成果卡使用八问体：

```text
一句话结论
→ 原来遇到什么问题
→ 问题原因分析
→ 当时有哪些可能做法
→ 本阶段做了什么
→ 遇到的困难和处理方式
→ 当前结果
→ 本阶段没有解决的问题
→ 下一步计划
```

交接书使用同一主体，并固定以下节：

- §0 交接信息：两行以内；
- §9 本次产生或更新的成果卡：一行管理指针；
- §10 接收人先检查什么：一行管理指针；
- §11 需要人工决定什么：问句清单；
- §12 工作流交接补充：一行管理指针。

§11 必须写明：不从沉默推定同意。

## 5. 自成一体

首次出现假设、方法、最近邻、预算、判据、台账、档位、挑战条目或代号时，必须展开为：

```text
它是什么 + 一句话解释
```

只能使用本文件、附录或机读块中已有事实。缺少解释材料时不编造，写“未记录”。

## 6. 数字双写

正文中的关键数字使用口语值加原始记录：

```text
110 个核心任务完成 54 个（core 54/110）
约 4.209 秒（台账原记：4.208571081515402 秒）
```

规则：

- 口语值不得改变数量级、单位和边界；
- 原值放在括号中；
- 数字必须能追溯到本文件、附录或机读记录。

## 7. 代码式记号

等号赋值、算术式、版本号、任务号、求解器名、批次名、条款代号和英文字段名不得作为主语或谓词直接进入正文。

写法：

```text
中文称谓（台账代号 X）
中文称谓（台账原记：...）
```

例外：

- 文献与方法代号，例如 Therm-FM、ARO、GFN；
- 学科阈值符号，例如 ε_rank、f_lo。

这些例外首次出现时仍要用中文解释。

## 8. 句子与括号

- 短句为主，通常不超过 45–60 个字；
- 纯列举长句可以保留；
- 一句至多一个括号；
- 禁止嵌套括号；
- “先说结论”“综上所述”类路标每份最多两次；
- 结论先行，不先铺过程。

## 9. 空与缺

- 整节无内容：写一行“（本项无记录）”；
- 字段无内容：写“未记录”；
- 状态用白话四类：已完成、部分完成、受阻、待定，可加限定语；
- 原枚举和机器状态放附录B。

不得用空白、省略号或占位词伪装成没有记录。

## 10. 安全网

- frontmatter 和附录B承载全部治理要素：SR ID、状态、支撑材料、人工决定、下一工作流等；
- 附录B与 frontmatter 必须同源同步；
- 迁移或重写旧稿时，原文全量保留在 §9 或附录C，供回溯；
- 产出后运行机读校验；
- 校验通过只表示结构与写作规则通过，不证明科学结论正确。
