# 任务范围与文件安排

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

在新请求或范围变化时简要记录目标、文件位置、权限和完成标准；用于需要留存任务安排的项目。按任务内容自然使用，不要求用户说出技能名或指定姓名。

## 先看什么

先读用户请求、适用的项目说明和直接相关的现有材料。已有决定继续有效，只询问会实质影响结果的缺失信息。

## 怎么做

1. 提取用户的逐条要求及已有决定，合并重复项，保留原意。
2. 查当前项目目录，明确哪些文件会改、哪些结果需要保存；优先现有目录。
3. 写清预期结果、允许的动作和验证方法，负责人可写角色或留空。
4. 只有真实的权限或输入缺口才提问，已授权的本地工作直接继续。

不重复生成测试报告、事实日志或设计文档；任务安排不代表结果已经完成。

## 交付什么

按实际用途选用本目录模板，删除不适用部分；简单回答无需另存。过程记录按项目、上海记录日和规范类型定位唯一日文件，任务为独立条目，不按内容简述或运行ID拆文件；无真实内容不创建。正式方案、API说明、手册等实体文档按对象身份持续维护，不能换名规避日记录规则。

- [20260912-项目治理-输出模板](assets/20260912-项目治理-输出模板.md)

需求记录按 A 级生成；沿用模板必需结构，管理字段集中在附录，不在正文堆叠编号。

## 怎么检查

目标、文件、完成标准清楚，没有新增用户未要求的范围。

本技能直接完成其范围内工作，必要方法已写入本目录。使用现有工具，不递归调用其他技能，不为普通任务增加管理表、额外角色或重复确认。


## 新增文件先确定唯一去处

写入前先判定文件用途，查现有归属配置，明确专题、稳定成果对象、现行母版与生命周期，再选择唯一文件夹。没有匹配类型时先提出归属并更新已有配置，不先把文件写在根目录或临时建Agent/任务/日期目录。需求与日志按现有日文件追加；研究正文按用途与对象持续维护，日期放文件名或元信息，不代替对象文件夹。

默认交付实际修订正文和必要图表，不每轮附带修改说明、逐句对照、编译检查或交付流水。用户明确要求的问答、独立评审和必要来源保留；专业依据在现有母版维护，过程原件留已有内部运行，不换名专题报告规避。成效目录根和各专题根只作阅读导航；专题内按配置的分类/对象放文件。源稿、专用图和附件随对象，跨成果共用图只有一份母版；编译临时文件与补丁不进成果区。

真实采用关系不明的稿件标待确认，不按日期、大小或“最新”字样自行认定当前稿。被替代版本成套只读保存，保持旧引用与恢复关系。历史具名决定原件精确保留，不作为新日记录生成入口。一次工作结束应核对新增文件均有明确归属，更新当前阅读入口，不额外生成管理报告。
