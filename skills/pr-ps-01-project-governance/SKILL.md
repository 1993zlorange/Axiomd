# 任务范围与文件安排

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

在新请求或范围变化时简要记录目标、文件位置、权限和完成标准；用于需要留存任务安排的项目。按任务内容自然使用，不要求用户说出技能名或指定姓名。

## 先看什么

先读用户请求、适用的项目说明和直接相关的现有材料。已有决定继续有效，只询问会实质影响结果的缺失信息。

## 怎么做

1. 提取用户的逐条要求及已有决定，合并重复项，保留原意。
2. 查当前项目目录，明确哪些文件会改、哪些结果需要保存；优先现有目录。
3. 写清预期结果、允许的动作和验证方法，负责人可写角色或留空。
4. 只有真实的权限或输入缺口才提问，已授权的本地工作直接继续。

不重复生成测试报告、事实日志或设计文档；任务安排不代表结果已经完成。

## 交付什么

按实际用途选用本目录模板，删除不适用的部分；简单回答无需另存文档。需要文件时使用项目已有目录，命名为 `YYYYMMDD-内容简述-文档类型.扩展名`。

- [20260912-项目治理-输出模板](assets/20260912-项目治理-输出模板.md)

需求记录按 A 级生成；沿用模板必需结构，管理字段集中在附录，不在正文堆叠编号。

## 怎么检查

目标、文件、完成标准清楚，没有新增用户未要求的范围。

本技能直接完成其范围内工作，必要方法已写入本目录。使用现有工具，不递归调用其他技能，不为普通任务增加管理表、额外角色或重复确认。
