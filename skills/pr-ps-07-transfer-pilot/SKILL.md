# 跨项目方法迁移

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

把其他项目的规则、模板、技能或工具适配到当前项目并小范围验证；用于复用已有方法。按任务内容自然使用，不要求用户说出技能名或指定姓名。

## 先看什么

先读用户请求、适用的项目说明和直接相关的现有材料。已有决定继续有效，只询问会实质影响结果的缺失信息。

## 怎么做

1. 核对来源版本、许可、依赖和原用途，识别私有内容与固定路径。
2. 比较当前项目的目标与环境，决定直接使用、修改后使用或不采用。
3. 在有限范围适配路径、字段和操作方式，保留来源且不覆盖原文件。
4. 运行代表性例子，记录效果、限制、兼容性及撤回办法，再完成授权范围内的迁移。

不得复制凭据、私有证据和另一项目专有结论。明确的迁移请求无需重复批准同一动作。

## 交付什么

按实际用途选用本目录模板，删除不适用部分；简单回答无需另存。过程记录按项目、上海记录日和规范类型定位唯一日文件，任务为独立条目，不按内容简述或运行ID拆文件；无真实内容不创建。正式方案、API说明、手册等实体文档按对象身份持续维护，不能换名规避日记录规则。

- [20260912-迁移试点-输出模板](assets/20260912-迁移试点-输出模板.md)

## 怎么检查

当前项目能实际使用，来源可查，失败能恢复，未迁移部分明确。

本技能直接完成其范围内工作，必要方法已写入本目录。使用现有工具，不递归调用其他技能，不为普通任务增加管理表、额外角色或重复确认。
