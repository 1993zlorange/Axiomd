# 软件功能测试

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

独立验证软件功能、用户路径和错误处理，报告可复现问题；适用于功能检查、回归和交付前测试。按任务内容自然使用，不要求用户说出技能名或指定姓名。

## 先看什么

先读用户请求、适用的项目说明和直接相关的现有材料。已有决定继续有效，只询问会实质影响结果的缺失信息。

## 怎么做

1. 从用户要求和有效需求中列出预期行为、测试范围和运行环境；缺少正式文档时标明依据和假设。
2. 在隔离环境执行完整路径，覆盖正常、边界、无效输入、权限、重复提交、依赖失败及恢复。
3. 界面用真实浏览器检查可见状态、网络响应、刷新持久化、宽窄屏和键盘焦点；接口检查响应内容和实际数据变化。
4. 为缺陷记录最少复现步骤、输入、预期、实际、版本和证据，区分产品缺陷与环境问题。
5. 按影响给出通过、未通过或未能验证的结论，以及覆盖范围和剩余风险。

测试请求不自动授权修改产品代码或真实业务数据。不能把 HTTP 200、静态截图或旧测试当作完整功能证据。

## 交付什么

按实际用途选用本目录模板，删除不适用的部分；简单回答无需另存文档。需要文件时使用项目已有目录，命名为 `YYYYMMDD-内容简述-文档类型.扩展名`。
