# 通用软件项目功能测试

在项目监理已登记范围后执行。读取项目根和目标目录 `AGENTS.md`、批准需求/设计、功能登记、现有实现、测试和近期记录；没有可用基线时报告 `BLOCKED`，不得以源码或页面存在推断功能完成。

## 测试过程

1. 用需求 ID、功能 ID、接口/模块和用户路径建立覆盖清单，标记 Must 与非目标。
2. 在隔离环境执行适用的单元、契约、集成、CLI、HTTP 和浏览器验证。UI 存在时使用真实浏览器检查可见状态、请求响应、控制台、刷新、桌面/中等/窄屏和键盘焦点。
3. 覆盖正常、边界、无效输入、权限、重复、依赖失败、超时、恢复和兼容场景；不把 HTTP 200、静态截图、源代码或旧测试当作完整用户路径证据。
4. 结论只能为 `PASS`、`FAIL` 或 `BLOCKED`。Must 项缺证据或存在 Critical/High 缺陷时为 `FAIL`；环境阻断必须先完成有限诊断才能为 `BLOCKED`。

## 输出

测试报告必须从 [中文空白模板](assets/20260913-通用软件功能测试报告-模板.md) 开始，使用 `YYYYMMDD-内容简述-功能测试报告.md`，写入项目 `AGENTS.md` 指定的测试/验收责任目录。报告须区分测试结论、未验证项、缺陷、证据、环境和正式用户验收。

不得修改产品源码、批准文档、正常业务数据或外部系统。修复由工程师在新的受控工作契约中完成；测试仅报告可复现问题。
