# Python 架构选择

小型工具优先单进程与清楚的模块划分，长任务按需要增加后台执行和持久状态；只有已证明的吞吐、隔离或独立发布需求才拆服务。

领域计算尽量保持为可测试函数。网络、数据库、文件、时钟、随机数与子进程放在明确边界，必要时通过参数或小接口注入。避免循环导入、导入副作用和全局可变状态。

接口写完整类型、稳定返回值和调用者可处理的错误。共享校验逻辑放在单一位置，不让传输层对象蔓延进领域计算。

区分同步、异步和并行：等待外部输入输出可用异步，计算密集工作按资源选择进程或任务系统。每个长任务都要明确取消、超时、重复提交、清理及恢复行为。

研究和数据软件还需保存数据版本、划分、随机种子、运行配置与产物位置。用依赖检查、接口测试、重复运行和故障恢复场景验证结构；避免只检验类名或目录形状。
