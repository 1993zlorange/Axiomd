# 软件详细设计说明

设计说明把明确需求变成实现所需信息。先给总体结构与主要取舍，再按模块写细节。

## 总体内容

写目标、当前系统、范围、质量要求、外部依赖、模块关系、数据流、部署方式和关键运行路径。用少量图解释结构，不以图替代接口和数据定义。

## 每个模块

写用途和非职责、输入输出、内部结构、算法或伪代码、状态转换、依赖、资源使用、错误和清理。接口列参数类型、必填项、默认值、合法范围、响应、错误、幂等性、权限和兼容规则。

## 数据与运行

写表和字段、约束、索引、事务、并发、版本和迁移；写配置来源、秘密注入、日志、超时、取消及故障恢复。离线要求、网络访问和持久化边界须与项目一致。

## 检查

用一条正常路径和主要失败路径走读，确认每项重要需求对应设计与测试。实现人员应能据此写代码，不必自行决定核心行为。列出实施顺序、恢复办法及真正待决定的事项。
