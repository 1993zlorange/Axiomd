# 项目功能测试报告模板

## Run identity

- 运行编号和带时区的本地时间
- 项目修订号；无法使用 Git 时记录文件哈希
- Python、Node、浏览器和操作系统版本
- 服务启动命令、隔离数据路径、端口和测试网址
- 需求/设计版本和批准状态

## Verdict

只填写一个结论：`通过`、`失败`或`阻塞`。

汇总总检查项，以及通过/失败/阻塞/不适用数量、路由覆盖、按钮和表单覆盖、API 覆盖、视口覆盖和测试套件结果。

## Defects

For each defect include:

- 稳定的缺陷编号；
- 严重度：严重、高、中或低；
- 分类，例如 `NO_RESPONSE`、`WRONG_RESPONSE`、`STATE_MISMATCH`、`CONSOLE_ERROR`、`ACCESSIBILITY` 或 `VISUAL`；
- 需求和设计引用；
- 确切页面/控件或 API；
- 前置条件和编号复现步骤；
- 预期结果；
- 实际结果；
- HTTP 请求/响应、控制台错误和持久化状态证据；
- 截图或追踪文件路径；
- 可能的责任层级，但不得把它表述为已证实的根因；
- 修正后所需的针对性复测。

## Coverage matrix

覆盖矩阵必须包含完整检查清单，而不只是失败项。每一行“通过”都必须写明断言和证据。

## Evidence index

列出报告、截图、追踪文件、响应捕获、数据库观察、单元测试输出、架构检查和有意省略的证据。

## Residual risks and exclusions

将未测试范围、不可用依赖、延后的 R1-B/R1-C 功能和证据强度限制与实际产品缺陷分开记录。
