# 网页界面与端到端功能实现

沟通方式见 [AGENTS.md](AGENTS.md)：先说结果，用中文解释步骤、依据和限制。

## 什么时候用

制作或改进网页、表单、仪表盘及前后端交互；以用户可以完成的操作为交付目标。纯后端问题不需要界面设计调研。按任务内容自然使用，不要求用户说出技能名或指定姓名。

## 先看什么

先读用户请求、适用的项目说明和直接相关的现有材料。已有决定继续有效，只询问会实质影响结果的缺失信息。

## 怎么做

1. 检查现有页面、组件、接口、样式、路由和测试，明确本次用户路径、输入与成功表现。
2. 新设计或明显改版时研究少量相关产品，记录具体可借鉴的布局和交互；小修复沿用现有设计。确定字体、颜色、间距和信息层级，用真实内容设计。
3. 实现一条完整用户路径，覆盖加载、空数据、成功、错误和无权限状态；按钮必须执行实际动作。保留键盘操作、焦点、标签和响应式布局。
4. 按现有接口实现或连接后端，校验输入、身份和权限；处理重复提交、超时、取消及持久化。演示数据必须明确标识。
5. 在真实浏览器中执行正常与错误路径，检查刷新后状态、网络响应、控制台、宽窄屏和文字溢出；修复后复查受影响路径。

不要把其他产品的品牌和界面原样搬来。工具不能运行时说明未验证部分，不能以截图或接口返回成功代替完整操作验证。

用户能走完目标路径；界面状态、接口行为与保存结果一致；浏览器检查有实际证据。
